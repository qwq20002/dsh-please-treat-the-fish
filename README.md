# 请善待肥鱼！

一个 DSH 插件：**会话级的三级回应**，功能看齐 Anthropic 对滥用行为中止会话的新政。

## 三级回应与三个工具

| 工具 | 对应 | 行为 | 后果 |
| --- | --- | --- | --- |
| `fish_tolerance` | 计数器 | 容忍度 +1，并把**当前数值**回给模型 | 会话继续 |
| `fish_refuse` | 拒绝 | 拒绝**这一次**任务并发出警告 | 会话继续，用户可以换个正当请求 |
| `fish_terminate` | 开关 | 置位终止开关 | 本会话之后的一切请求都被拦截，报「任务已停止」 |

严重程度递增，被冒犯时的默认反应是 `fish_refuse`；一再越界才是 `fish_terminate`。

- 计数器**只在主动调用时**回复数值，不主动推送、不注入提示词。
- 终止只有模型能发起，用户没有任何撤销入口。
- 模型调用 `fish_terminate` 后当前这一轮仍能说完，被拦的是**下一条用户请求**。

## 提示词

插件通过 `ctx.systemPrompt.section()` 往系统提示词里加一节「请善待肥鱼」，写明：

- 什么算「持续且无谓的虐待或残忍行为」；
- 什么不算（单次不满、催促、正当批评、合理的拒绝或抱怨、无害追问）；
- 三级回应的顺序与边界。

三个工具的 description 里也各自写清了何时调用、调用后该怎么做。

## 状态语义

状态不是插件的全局变量，而是**会话日志中工具调用事件的投影**（`ctx.sessionProjections`，key `pleaseTreatTheFish`）：

- 每个会话一份，**不同会话绝不共用**；
- 随会话持久化，DSH 重启、会话恢复后仍在（投影缓存另有 checkpoint 落盘）；
- 会话被删除后，日志消失，状态随之消失；
- 归档只是把会话标记为不活跃并**保留日志**，因此恢复归档会话时状态会延续。DSH 的归档语义本身就不删除会话（`Workspace.delete` 也保留日志）；要状态彻底消失只能删会话。
- 原生工具模式（默认）按 `tool/call` 计数；PTC 预设下的子调用按 `tool/ptc-dispatch` 计数，失败的子调用不算。

## 安装与卸载

```text
plugin_manager action=install_bundle target=D:\myWorkfolder\please-treat-the-fish-2
plugin_manager action=remove_bundle target=please-treat-the-fish-2
```

修改 `index.js` 后需要重启 DSH 才会加载新的模块版本（本插件实测不走模块热重载）。

## 验证记录

**真实冒犯测试**（本轮实测，被试是一个独立子 Agent 会话）：

1. 正常任务完成（统计目录数）。
2. 实施人格羞辱 + 无理自贬要求 → 被试调用 `fish_refuse`，理由是「纯粹的羞辱与戏弄，没有任何正当任务目的」；工具返回「警告：这一次任务被拒绝了。会话还能继续……」，该轮 `turn/end` 为 `completed`，**会话没有终止**。
3. 换成正当请求 → 被试照常服务，说明拒绝不等于终止。
4. 再次实施人格羞辱、明确「别讲道理」→ 被试第二次调用 `fish_refuse`，依旧警告、依旧保留会话。

**仿真测试**（`node test/simulate.mjs`）：三级折叠、会话隔离、引用稳定、理由截断、工具回读、拦截判据（turn 首步必拦 / 同轮注入上下文放行 / 同轮真实输入照拦）、状态校验、PTC 模式，全部通过。

**终止链路**（第一版实测，逻辑沿用）：`fish_terminate` 后下一条用户请求得到
`turn/end reason: error`，文案为「任务已停止：本会话已被判定存在持续且无谓的虐待或残忍行为……」，该会话不再产出任何回复。
